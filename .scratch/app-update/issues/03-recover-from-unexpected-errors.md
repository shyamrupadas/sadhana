# 03: Восстановление после неожиданных ошибок интерфейса и API

**What to build:** При неожиданном сбое пользователь видит «Проверяем обновление…», а приложение один раз пытается восстановиться через обновление. Если это не удалось в пределах 15 секунд, появляется понятная страница ошибки с кнопкой «Обновить страницу». Неожиданные ошибки сохранения сна и отметок привычек участвуют в том же сценарии; циклов перезагрузки и повторной отправки команд нет.

**Blocked by:** 02 — Фоновое автоматическое обновление PWA

**Status:** ready-for-agent

- [ ] В общий сценарий восстановления включены неожиданные ошибки отображения интерфейса, загрузки маршрутов/чанков и запросов API. Асинхронные ошибки сохранения подключены явно; одного React Error Boundary не считается достаточным.
- [ ] Неожиданный отказ сохранения данных сна или отметки привычки запускает восстановление и не ограничивается незаметным откатом оптимистического значения. Необходимые действия по согласованности локального состояния сохраняются.
- [ ] Только после неожиданной ошибки показывается «Проверяем обновление…». Предел ожидания — 15 секунд на всю попытку; следующая параллельная ошибка или смена стадии проверки/подготовки не начинает отсчёт заново.
- [ ] При доступной и подготовленной в пределах ожидания другой сборке выполняется одна автоматическая перезагрузка общим механизмом из 02. Ранее отправленная команда после неё не воспроизводится.
- [ ] Если другой сборки нет, проверка/подготовка не удалась или ожидание истекло, появляется страница «Что-то идёт не так, обновите страницу или попробуйте позже» с кнопкой «Обновить страницу». Автоматической перезагрузки той же сборки нет.
- [ ] Повторный неожиданный сбой после автоматического перезапуска до успешного восстановления сразу показывает страницу ошибки без второго автоматического перезапуска. Если фактически снова запущена прежняя сборка, обновление не объявляется успешным.
- [ ] Ошибки чанков, API и интерфейса используют общий лимит попыток; прежний отдельный chunk-retry не добавляет ещё одну перезагрузку. Одновременные сбои присоединяются к одному восстановлению.
- [ ] После показа страницы ошибки поздняя готовность worker, внешние события его обновления и периодический таймер не перезапускают приложение. Установка может продолжиться, но переход остаётся под контролем ручного повтора.
- [ ] Кнопка разрешает новую ограниченную попытку с ожиданием до 15 секунд: готова другая сборка — переключаемся; новой сборки нет — по явному нажатию перезагружаем текущую страницу; ошибка проверки/подготовки или таймаут — остаёмся на странице ошибки с возможностью повторить позже.
- [ ] Экран ошибки и кнопка работают независимо от успешной загрузки упавшей фичи и её запросов. Если защиту от повторов нельзя сохранить, приложение не запускает потенциально бесконечный цикл.
- [ ] Отсутствие связи обрабатывается как сейчас. Штатная авторизация и ожидаемые ошибки ввода не превращаются в неожиданные сбои только из-за неуспешного HTTP-статуса.
- [ ] Интеграционные проверки через видимый UI и внешние эффекты подтверждают вход в восстановление из ошибки UI и API, одну общую попытку, предел 15 секунд, страницу ошибки и ручной повтор, блокировку позднего reload и отсутствие повторной команды.
- [ ] Проверки отличают успешный запуск документа от успешного восстановления интерфейса и необходимых данных. Сценарий повторного сбоя воспроизводится с защитой, сохранённой между загрузками, без привязки к приватной структуре координатора.

## Границы и проверка

Источник: [принятая спецификация](../spec.md), сценарий неожиданной ошибки и правило одной попытки. Повторно не реализуются ресурс версии, расписание, готовность PWA или toast из предыдущих тикетов.

Новые специализированные PWA/E2E и автоматизация двух сборок не требуются. Основные регрессии проверяются через существующие Vitest/RTL providers, точные HTTP-подмены, управляемые часы и локальные браузерные события. Не требуется повторять вручную всю матрицу ошибок, уже проверенную интеграционно; применяется общий порядок завершения задачи.

Обратная совместимость API, серверный version gate и черновики не добавляются. Старый клиент без полученного механизма сохраняет прежнее поведение и может требовать ручного обновления.
