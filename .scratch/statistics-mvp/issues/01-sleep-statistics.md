# 01: Статистика сна целиком

**What to build:** Пользователь может локально поднять проект на существующей dev-базе, увидеть перенесённую историю сна в днях и средних по календарным неделям, месяцам и годам, непрерывно просматривать её и получать актуальные показатели после изменения сна на главной.

**Blocked by:** None (can start immediately)

**Status:** awaiting-human-review

- [x] Первичные данные сна хранятся в типизированной модели: владелец, дата записи, полные местные дата/часы отбоя и подъёма, минуты дневного сна. Длительность вычисляется; операции чтения и записи сна работают с этой моделью. Изменение сна сохраняет отметки привычек.
- [x] В этом тикете реализована и применена на существующей постоянной dev-базе миграция прежнего сна. Сохраняются владелец, дата записи, полные местные дата/часы отбоя и подъёма и исходные минуты дневного сна, без UTC-конверсии и повторного сдвига отбоя. Производная длительность не переносится как первичный факт. Сброс базы и замена её истории синтетическими данными для проверки результата не требуются.
- [x] При переносе автоматическая сверка в обе стороны проверяет первичные значения сна, владельцев и даты; количества и уникальность проверяются дополнительно. Некорректные значения, коллизии или расхождения останавливают перенос до разбора. Прежние поля сна удаляются только после успешной сверки; определения и отметки привычек сохраняются. Повторный запуск мигратора не переносит данные заново и не меняет уже применённые миграции.
- [x] После миграции пользователь может запустить API и web обычным локальным способом, войти в существующий dev-аккаунт, открыть прежнюю историю сна и сохранить новые значения. Ещё не перенесённые привычки сохраняются и доступны в текущем ежедневном учёте до второго тикета; новая статистика привычек пока не требуется.
- [x] Новый авторизованный диапазонный API статистики поддерживает дни, недели, месяцы и годы, включённое начало, исключённый конец и календарный срез устройства. Контракт описан в TypeSpec, производные артефакты сгенерированы. Чужие данные не возвращаются.
- [x] Недели идут с понедельника по воскресенье, месяцы и годы календарные. Текущий период ограничен сегодня включительно; будущие даты исключены из выборок. Сервер не подменяет срез устройства своей датой и не переводит введённые часы в другой часовой пояс.
- [x] Пределы блока — 48 дней, 24 недели, 12 месяцев или 4 года; дополнительно проверяется календарная длина, максимум 1461 исходный день и один технический предыдущий день. Неверный диапазон и превышение лимитов отклоняются явно.
- [x] Ответ содержит границы/срез, общую нижнюю границу содержательной истории и календарные колонки по возрастанию. Пустые строки БД не задают начало истории, пустой аккаунт показывает сегодня. Первый агрегированный период начинается с календарной границы; технический предыдущий день не становится колонкой и не включается в средние.
- [x] Длительность даты d использует отбой точной даты d−1, подъём d и дневной сон d. Разрыв истории не заменяется предыдущей существующей строкой. Без одного из времён ночи длительность неизвестна и не считается нулём.
- [x] Отбой, подъём и общая длительность имеют независимые выборки. Средний отбой 23:00 и 01:00 — 00:00; средний подъём 11:00 и 13:00 — 12:00, а 00:00 и 12:00 — 06:00. Средние округляются до минуты; ответ сохраняет проверяемые суммы и счётчики.
- [x] Пустой дневной сон даёт 0 минут в расчётах, включая отсутствующие календарные дни. Среднее 30 и 60 минут за семь дней — около 13 минут; полностью нулевой период отображается прочерком. Известный дневной сон учитывается независимо от наличия ночной длительности.
- [x] В таблице строки «Подъём», «Дневной сон», «Сон (итого)», «Отбой»; время суток имеет формат HH:mm, длительность — H:mm. Ширина колонок данных во всех масштабах — 3 rem, закреплённых названий — 5,5 rem. Нет надписи «Дата», отдельного заголовка «Сон», подсветки выбранной колонки, счётчиков дней и блока стрелок с периодом.
- [x] Работает непрерывная горизонтальная прокрутка жестом, трекпадом, полосой прокрутки, перетаскиванием мышью и клавишами влево/вправо при фокусе на таблице. Смена масштаба сохраняет календарный ориентир; после выхода выбранной даты из видимой области ориентиром становится последняя видимая дата. «К сегодня» возвращает к правому краю.
- [x] В DOM находятся только видимые колонки и до трёх запасных с каждой стороны. В памяти — не более трёх блоков текущего масштаба/набора строк вместе с предзагрузкой. Дальние блоки освобождаются и повторно запрашиваются при возврате без изменения логической шкалы и положения даты.
- [x] Соседний блок загружается заранее в пределах истории и среза. Неполученный участок показывает крупный плейсхолдер и ограничивает дальнейшее движение в него; полученные даты доступны. Ошибка предлагает «Повторить» и не превращается в пустые значения; успешная загрузка сохраняет данные и положение таблицы.
- [x] Кэш различает пользователя, масштаб, диапазон, срез и набор строк/фильтры. Смена аккаунта отменяет приватные запросы и очищает приватный кэш; поздний ответ прежней сессии не показывается новому пользователю. Смена масштаба не накапливает неограниченный кэш.
- [x] После успешного изменения сна инвалидируется статистика пользователя и обновляется открытый блок. Изменение отбоя d обновляет длительность d+1 и соседние календарные периоды. Смена локальной даты обновляет срез.
- [x] Чтение ограничено запрошенным диапазоном с техническим предыдущим днём; расчёты выполняются на API без сохранённых агрегатов и запросов на каждый день. Клиент форматирует готовые показатели.
- [x] На существующей dev-базе проверены перенесённая история сна, работа приложения и сохранение новых значений. Отдельные синтетические сценарии защищают крайние случаи и отказ переноса. Автоматические проверки защищают расчёты через HTTP API, границы/лимиты, изоляцию владельцев, обновление после записи, загрузку/ошибку/повтор и навигацию. Реальная прокрутка и виртуализация проверены в браузере по порядку завершения задачи; её визуальная оценка выполняется на dev.

## Граница задачи и общего выпуска

Это первый функциональный блок единого MVP. Он включает схему, перенос прежнего сна, рабочие операции, таблицу во всех масштабах и необходимые проверки своего поведения. После его выполнения проект должен запускаться локально на существующей dev-базе, чтобы пользователь мог проверить сон на своей прежней истории. Полнота ещё не реализованной статистики привычек не является условием его приёмки. Предусмотренная спецификацией общая граница истории должна расшириться данными привычек при завершении следующего блока.

Миграция сна и её сверка реализуются здесь как часть окончательного перехода, а не как временный перенос для демонстрации. Синтетические данные дополняют проверку существующей dev-истории. В третьем тикете эта же миграция повторно проверяется в полной репетиции перехода со старой схемы; отдельный преобразователь сна там не создаётся. Согласованная очистка бесхозных отметок относится ко второму тикету и не входит в перенос сна.

В production выпускается итог всех трёх тикетов. Поддержка прежнего API, временные адаптеры, двойная запись и самостоятельный промежуточный выпуск не требуются. Это не отменяет проверок реализованного поведения на dev. Редактирование истории на странице статистики, окончательный дизайн и обновление PWA вне задачи.
