# Сверка текущих настроек Railway перед переключением

Type: task
Status: resolved
Blocked by: 04 — Независимый выпуск приложений прежними поставщиками

## Question

Какие фактические настройки действующего production-сервиса Railway необходимо сохранить или изменить при перепривязке к монорепозиторию, и нет ли ограничений, которые меняют согласованную схему Docker-сборки API из корня workspace и автодеплоя из `master`?

## Answer

- В [проекте `sadhana-tracker`](https://railway.com/project/fdf5c84e-42cc-4e8e-8f9a-89d18b1fc746?environmentId=c2548a1c-b4ec-4df2-addf-6a444d82cf74), окружение `production`, работает один сервис `sadhana-backend`. [Настройки сервиса](https://railway.com/project/fdf5c84e-42cc-4e8e-8f9a-89d18b1fc746/service/9aeee13e-7d04-4a08-b0a5-6988c4af41cb/settings?environmentId=c2548a1c-b4ec-4df2-addf-6a444d82cf74) привязаны к `shyamrupadas/sadhana-backend`, ветке `master`; GitHub autodeploy включён. Root Directory не задан, то есть используется корень репозитория. `Wait for CI` выключен. Builder — Railpack с определённым им Node 22.22.0; отдельный Dockerfile path и custom build/start commands не заданы. Watch paths пусты. Pre-Deploy Command и Healthcheck Path не заданы. Railway Config File не задан. В production работает одна реплика в EU West (Amsterdam), Serverless выключен, restart policy — On Failure с 10 попытками. На диаграмме окружения отдельный volume не показан.
- Публичные адреса — `api.sadhana-tracker.com` и `sadhana-backend-production.up.railway.app`; оба направлены на порт **8080**. Есть внутреннее имя `sadhana-backend.railway.internal`. В [переменных сервиса](https://railway.com/project/fdf5c84e-42cc-4e8e-8f9a-89d18b1fc746/service/9aeee13e-7d04-4a08-b0a5-6988c4af41cb/variables?environmentId=c2548a1c-b4ec-4df2-addf-6a444d82cf74) видны шесть имён: `COOKIE_SECRET`, `CORS_ORIGIN`, `DATABASE_URL`, `JWT_REFRESH_SECRET`, `JWT_SECRET`, `NODE_ENV`. Пять из них (`COOKIE_SECRET`, `DATABASE_URL`, `JWT_REFRESH_SECRET`, `JWT_SECRET`, `NODE_ENV`) показаны также как используемые shared variables; `CORS_ORIGIN` — переменная сервиса. `PORT` отдельно не задан; нынешний сервер по коду использует 8080 по умолчанию. Значения переменных не раскрывались и не записывались. Публичный `GET https://api.sadhana-tracker.com/` 2026-10-02 вернул HTTP 200 и `{"root":true}`.
- При переходе сохранить существующий Railway project/environment/service, домены, порт 8080, переменные и их источники, регион и одну реплику. Перепривязать Git source к монорепозиторию, оставив `master` и корень workspace в качестве Root Directory; `/apps/api` указывать нельзя. Перейти с Railpack на корневой Dockerfile с Node 24, явно настроить watch paths для API, общего контракта и всех входов сборки, включить `Wait for CI`, добавить Pre-Deploy Command для собранного мигратора и Healthcheck Path `/`. До перепривязки проверить Docker-образ, его команды и доступность всех SQL-файлов; смену builder и Pre-Deploy выполнять только в согласованном порядке переключения, чтобы не нарушить текущий выпуск. Действующие переменные и адреса сохранить; при необходимости добавить отдельный direct URL для мигратора. Тип текущего `DATABASE_URL` и точную базу/ветку без чтения значения здесь подтвердить нельзя; это вход в задачу «Сверка исторических миграций в production Neon».
- Фактические настройки **не препятствуют** согласованной схеме корневой Docker-сборки и автодеплоя из `master`, но сейчас у сервиса нет необходимых CI-gate, фильтра путей, Pre-Deploy и healthcheck. Настройки Railway не менялись.

## Comments

- Это задача чтения настроек, а не переключения сервиса. В локальных репозиториях нет Railway-конфигурации или привязанного CLI; нужен доступ к панели действующего сервиса. Сверить project/environment/service, Git-репозиторий и ветку, autodeploy/Wait for CI, Root Directory, builder/Dockerfile path, build/start/pre-deploy команды, watch paths, healthcheck, `PORT`, домены, число реплик и наличие volume. По переменным достаточно имён и источников, без значений секретов; проверить имена `DATABASE_URL`, `JWT_SECRET`, `JWT_REFRESH_SECRET` и других используемых приложением переменных. Записать расхождения с решением «Независимый выпуск приложений прежними поставщиками» и ссылки/скриншоты настроек без секретов. Ничего в production пока не менять.
- Проверено 2026-10-02: в `../sadhana-backend` нет Railway-манифеста и CLI `railway` не установлен. Схема `src/plugins/env.ts` требует `DATABASE_URL`, `JWT_SECRET`, `JWT_REFRESH_SECRET`; дополнительно читает `NODE_ENV`, `JWT_EXPIRES_IN`, `JWT_REFRESH_EXPIRES_IN`, `CORS_ORIGIN`, а сервер читает `PORT`. Значения `.env` не просматривались. Текущий `npm start` компилирует TypeScript перед запуском, `npm run migrate` отдельно компилирует и запускает `dist/db/migrate.js`; фактические команды Railway по коду не установить.
- При первой попытке 2026-10-02 профиль MCP `chrome-devtools` был занят. После освобождения браузера владелец вошёл в Railway; настройки и имена переменных сверены непосредственно в панели без изменения production и без раскрытия секретов.
