# 09: Завершение перехода на единый контракт

**What to build:** Разработчик меняет публичный API в одном TypeSpec-источнике, а оба приложения используют полный общий контракт без старых параллельных схем и клиентов.

**Blocked by:** 04 — Регистрация, вход и обновление сессии через контракт; 05 — Создание, переименование и удаление привычек через контракт; 07 — Отметки привычек в записи дня через контракт; 08 — Вчерашний сон и статистика через контракт

**Status:** awaiting-human-review
Accepted: 2026-10-04

- [x] Все 14 операций представлены в TypeSpec, generated `ApiClient` и едином `ApiHandlers`; веб-вызовы и Fastify-адаптеры больше не зависят от прежних клиентских библиотек или двух YAML-копий.
- [x] Инвентаризация фактического HTTP-контракта сверена с результатом генерации: статусы, nullable/optional поля, cookie, `204`, ошибки и документированные побочные эффекты покрыты без намеренного изменения поведения.
- [x] Старые YAML и производные типы удалены только после успешных проверок web/API; при необходимости сохранённые MSW-моки типизируются новым контрактом.
- [x] Прямая генерация в CI выявляет как изменения, так и новые незакоммиченные generated-артефакты; типизация обоих приложений и тесты проходят после чистой установки.
- [x] ADR о прежнем источнике OpenAPI пересмотрен под TypeSpec; границы `app`, `features`, `shared` и исполняемые lint-правила остаются согласованными.
