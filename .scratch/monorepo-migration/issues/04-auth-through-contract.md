# 04: Регистрация, вход и обновление сессии через контракт

**What to build:** Пользователь регистрируется, входит и продолжает работу после истечения access token через новый общий клиент и API, сохраняя действующее поведение refresh cookie.

**Blocked by:** 03 — Первый сквозной TypeSpec-срез: список привычек

**Status:** awaiting-human-review
Accepted: 2026-10-04

- [x] TypeSpec и generated-интерфейсы описывают три auth-операции, фактические статусы и ошибки, входную refresh cookie и выходной `Set-Cookie` без refresh token в публичном JSON.
- [x] Публичный web-транспорт выполняет auth-запросы без bearer с `credentials: include`; защищённый транспорт асинхронно получает access token и сохраняет единственный параллельный refresh и прежние исходы 401/503.
- [x] Fastify-адаптеры сохраняют runtime JSON Schema, обработку ошибок и атрибуты cookie для HTTPS/HTTP, а типизированные обработчики получают нужный контекст без повторной проверки JWT в сервисах.
- [x] HTTP-тесты проверяют register/login/refresh, ротацию cookie, отсутствие cookie, неверные данные, истёкший токен и отсутствие refresh token в теле ответа.
- [x] В браузере работают регистрация, вход, обновление сессии и выход; новая web-версия остаётся совместимой со старым действующим API до переключения Railway.
