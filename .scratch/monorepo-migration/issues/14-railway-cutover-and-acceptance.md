# 14: Переключение Railway и приёмка

**What to build:** Действующий Railway-сервис выпускает API из монорепозитория с безопасным Pre-Deploy, а владелец принимает работу прежних web/API адресов и сохранность Neon.

**Blocked by:** 13 — Выпуск нового web со старым API

**Status:** ready-for-agent

- [ ] Перед изменением production пройдена согласованная ручная проверка готовности: зелёный CI, работоспособная пара новый web + старый API, успешная репетиция Neon, известные SHA и условия отката.
- [ ] Повторно подтверждено, что production-схема и признаки данных соответствуют 001–006; рабочий pooled URL и direct URL мигратора относятся к одной ветке. При расхождении переключение остановлено.
- [ ] В production один раз заполнен `schema_migrations` подтверждёнными 001–006 с точными суммами без выполнения исторических SQL; строки журнала сверены.
- [ ] В существующем Railway-сервисе сохранены домены, порт, переменные, регион и реплика; источник переключён на монорепозиторий `master` с корнем workspace, Docker, API watch paths, Wait for CI, Pre-Deploy и healthcheck `/`.
- [ ] Для уже опубликованного SHA явно выполнен `Deploy Latest Commit`; логи подтверждают успешный Pre-Deploy без повторного исполнения 001–006, успешный healthcheck и запуск нового API.
- [ ] Проверено, что ошибка Pre-Deploy или healthcheck не активирует новый API и позволяет остановить переключение на прежнем работающем deployment.
- [ ] На действующих адресах проверены HTTP-операции, auth/cookie, CORS, загрузка web, привычки, сон, статистика, PWA и агрегаты Neon. Владелец проверил запись/чтение через свою учётную запись; отдельный production-тестовый аккаунт не создавался.
- [ ] Зафиксированы успешные SHA и deployment IDs. При сбое возврат web или Railway deployment выполняется только после проверки совместимости со схемой и JSON-данными Neon; при несовместимости выбран исправляющий выпуск вперёд или отдельный план восстановления.
