# 01: Web в pnpm workspace

**What to build:** Разработчик может запускать и собирать прежний web из общего workspace, а его выпуск по-прежнему создаёт рабочий сайт на прежнем адресе и обращается к действующему API.

**Blocked by:** None (can start immediately)

**Status:** awaiting-human-review
Accepted: 2026-10-03

- [x] Web перенесён как отдельный приватный пакет pnpm; чистая установка из корня, lint, typecheck и production-сборка проходят на закреплённых Node 24 и pnpm.
- [x] Сохранились маршруты, три слоя фронтенда, публичные входные точки фич, PWA, production API URL и поведение текущего клиента.
- [x] Общий граф Turbo собирает web без ручной подготовки зависимостей; web можно запустить отдельно.
- [x] Workflow web подготовлен к установке и сборке из workspace и публикации артефакта web в прежний каталог VPS с прежними SSH-проверками, не меняя адрес и секреты.
- [x] Быстрая проверка локального сайта подтверждает вход, главный экран и статистику со старым API; production-публикация оставлена тикету переключения.

## Comments

- Локально проверены страницы входа и регистрации, редирект с защищённого маршрута и ответ `401` действующего API на неверный вход. Production-сборка содержит прежний API URL, manifest и service worker. Главный экран и статистика требуют авторизованной сессии; владелец 2026-10-03 оставил их проверку на приёмку.
- Web workflow проверяет push в `master`, а публикация VPS пока доступна только через ручной запуск из `master`. Автоматическую публикацию включает тикет 13 после проверки пары новый web — старый API.
- 2026-10-03 владелец вошёл в локальный web: действующий API вернул `200` на вход, `/habits`, `/sleep-records` и `/sleep-stats`; главный экран и статистика отобразились. Ручной критерий выполнен без production-публикации.
