# 13: Выпуск нового web со старым API

**What to build:** Пользователь получает новый web из монорепозитория на прежнем адресе, пока действующий API остаётся старым; эта переходная пара работает до переключения Railway.

**Blocked by:** 12 — Репетиция мигратора на временной ветке Neon

**Status:** awaiting-human-review
Accepted: 2026-10-05

- [x] Общий коммит проходит обязательный CI и автоматически выпускает web из `master` через прежний GitHub Actions → SSH → VPS; проверены опубликованный артефакт, SHA и встроенный API URL.
- [x] На действующем сайте проверена переходная пара новый web + старый API: вход, обновление сессии, привычки, записи дня, статистика, навигация и обновление PWA без ошибок ресурсов.
- [x] API Railway всё ещё привязан к прежнему backend-репозиторию; его домены, переменные и данные Neon не изменены этим выпуском.
- [x] При несовместимости или сбое web дальнейшее переключение остановлено; известен и проверен способ повторно выпустить прежнюю рабочую версию web.

## Comments

- Локально подготовлена автоматическая публикация web при push в `master`: workflow ждёт успешный CI того же SHA до `rsync`, при ошибке или ожидании свыше 15 минут не копирует файлы на VPS. Проверены `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`, синтаксис workflow, production API URL в собранном web и ответ локального Vite-сервера. Публикация и критерии действующего сайта остаются открытыми до коммита и push владельца. Владелец самостоятельно проверит пользовательские сценарии и PWA на действующем сайте после выкладки.
- Владелец принял тикет 2026-10-05 до фактической публикации web. Критерии выпуска и проверки действующего сайта выше остаются открытыми; перед переключением Railway требуется подтвердить их по пункту готовности тикета 14.
- Ретроспективное закрытие критериев после переключения: комментарии тикета 14 подтверждают успешные CI и web deploy для SHA `59fbde887bd72f2b53ca19efb895d42e94d6b595` (run `37353005150`), проверку владельцем переходной пары с auth, привычками, сном, статистикой и PWA, а также сохранение старого Railway deployment до переключения. Встроенный production API URL проверялся при сборке и в web workflow. Путь восстановления прежнего web проверен по рабочему коммиту `012858e` и его push workflow с публикацией `dist/` в прежний каталог; пробный production-откат не выполнялся, поскольку переходная пара работала. После переключения API этот прежний web-коммит нельзя выпускать без отдельной проверки совместимости с новым API (тикет 14).
