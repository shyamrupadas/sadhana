# 10: Безопасный мигратор с журналом

**What to build:** Оператор может применять SQL-миграции один раз, обнаруживать изменение уже применённого файла и безопасно повторять или параллельно запускать мигратор без повторного преобразования пользовательских данных.

**Blocked by:** 02 — API в общем workspace

**Status:** ready-for-agent

- [ ] Мигратор ведёт `schema_migrations` с уникальным упорядоченным идентификатором и SHA-256 точных байтов SQL; исторические файлы 001–006 не изменены.
- [ ] Отдельное прямое PostgreSQL-соединение держит session-level advisory lock; каждая новая миграция и её запись в журнал применяются одной транзакцией с ограниченными таймаутами.
- [ ] Повторный запуск пропускает совпадающие файлы; изменённая сумма, неизвестная версия, пропуск в последовательности и ошибка SQL завершают процесс ненулевым кодом.
- [ ] Предусмотрена отдельная однократная операция ретроспективного учёта только подтверждённых 001–006 без исполнения их SQL и без выдуманной даты первого применения.
- [ ] Интеграционные проверки на изолированной PostgreSQL покрывают пустую базу, ретроспективный учёт, повтор, конкурентный запуск и ошибку; пользовательские таблицы не меняются при повторе.
