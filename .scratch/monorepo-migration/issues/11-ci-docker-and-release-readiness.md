# 11: CI и Docker для независимых выпусков

**What to build:** Разработчик получает проверенный production-образ API и независимые правила выпуска web и API; общий коммит проходит обязательные проверки до публикации.

**Blocked by:** 09 — Завершение перехода на единый контракт; 10 — Безопасный мигратор с журналом

**Status:** awaiting-human-review
Accepted: 2026-10-05

- [x] На PR и каждый push в `master` обязательный CI после чистой установки напрямую регенерирует контракт, отклоняет изменённые и новые generated-файлы и запускает lint, typecheck, build и быстрые тесты нужных пакетов.
- [x] Многоэтапный Docker-образ из корня workspace содержит собранный API, контракт, runtime-зависимости, мигратор и SQL, но не web/инструменты сборки; установленная версия pnpm успешно выполняет изолированную production-упаковку.
- [x] CI собирает и запускает образ, проверяет `GET /` с успешным статусом, доступность мигратора и корректное прослушивание Railway-порта; Docker build не исполняет SQL.
- [x] Web workflow проверяет контракт и сборку перед `rsync --delete`, публикует артефакт web в прежний каталог и проверяет доступность сайта/API после копирования; действующие SSH-секреты, host key и production URL сохраняются.
- [x] Фильтры web и Railway перечисляют все фактические входы сборки: локальное изменение выпускает своё приложение, общий контракт или общая конфигурация — оба, одни документы — ни одно. Обязательный CI не пропускается из-за path-фильтра; конфигурация Railway Wait for CI, healthcheck и Pre-Deploy подготовлена к переключению.
- [ ] Локально и в CI проверены сочетания новый web + старый API и старый web + новый API для последующего условного отката.

## Comments

- Локально прошли `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` с временной PostgreSQL в Docker (21 тест API и 10 тестов контракта), прямая генерация контракта, `pnpm deploy --prod --legacy`, Docker build и `GET /` образа с `PORT=18080`. В образе есть шесть SQL и собранный мигратор, отсутствуют web и инструменты сборки. Production Neon не использовалась.
- По образцу референса CI запускает тесты и проверяет API-образ без PostgreSQL. Интеграционные тесты мигратора без `MIGRATION_TEST_DATABASE_URL` пропускаются; локально они проверены на временной БД. Образ собирается при изменении API, контракта или общих входов; обязательные проверки workspace выполняются всегда.
- Первый фактический запуск GitHub CI и проверка обеих переходных пар на реальных версиях остаются открытыми. Автоматические тесты проверяют HTTP-формы нового клиента и нового API, но не заменяют запуск нового web со старым API и старого web с новым API. Браузерный MCP `chrome-devtools` в этой среде недоступен; фактические переходные проверки запланированы перед выпусками в тикетах 13–14.
- Владелец принял тикет 2026-10-05. Последний критерий оставлен непроверенным; переходные пары нужно проверить перед соответствующими выпусками.
