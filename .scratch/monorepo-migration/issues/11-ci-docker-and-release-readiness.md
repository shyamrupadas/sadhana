# 11: CI и Docker для независимых выпусков

**What to build:** Разработчик получает проверенный production-образ API и независимые правила выпуска web и API; общий коммит проходит обязательные проверки до публикации.

**Blocked by:** 09 — Завершение перехода на единый контракт; 10 — Безопасный мигратор с журналом

**Status:** ready-for-agent

- [ ] На PR и каждый push в `master` обязательный CI после чистой установки напрямую регенерирует контракт, отклоняет изменённые и новые generated-файлы и запускает lint, typecheck, build и быстрые тесты нужных пакетов.
- [ ] Многоэтапный Docker-образ из корня workspace содержит собранный API, контракт, runtime-зависимости, мигратор и SQL, но не web/инструменты сборки; установленная версия pnpm успешно выполняет изолированную production-упаковку.
- [ ] CI собирает и запускает образ, проверяет `GET /` с успешным статусом, доступность мигратора и корректное прослушивание Railway-порта; Docker build не исполняет SQL.
- [ ] Web workflow проверяет контракт и сборку перед `rsync --delete`, публикует артефакт web в прежний каталог и проверяет доступность сайта/API после копирования; действующие SSH-секреты, host key и production URL сохраняются.
- [ ] Фильтры web и Railway перечисляют все фактические входы сборки: локальное изменение выпускает своё приложение, общий контракт или общая конфигурация — оба, одни документы — ни одно. Обязательный CI не пропускается из-за path-фильтра; конфигурация Railway Wait for CI, healthcheck и Pre-Deploy подготовлена к переключению.
- [ ] Локально и в CI проверены сочетания новый web + старый API и старый web + новый API для последующего условного отката.
