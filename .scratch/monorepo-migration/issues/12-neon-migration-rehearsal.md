- Репетиция 2026-10-05 на коммите `776717ecb95ac453237e70460fbd47745cb03d91`. В проекте Neon `sadhana-tracker` выбрана production-ветка `br-autumn-cake-ag06rp2m`; её дочерняя ветка `migration-rehearsal-2026-10-05` имеет ID `br-green-wave-agm9ommo` и direct endpoint `ep-green-bar-agg6ps2j.c-2.eu-central-1.aws.neon.tech`. Прежний pooled endpoint Railway `ep-flat-darkness-ag44hig2-pooler.c-2.eu-central-1.aws.neon.tech` взят из инвентаризации и локальной конфигурации; совпадение отпечатков всех пользовательских таблиц подтверждает, что копия создана от рабочей базы. Подключение к обеим веткам выполнялось к `neondb` от роли `neondb_owner`; URL и пароль не записывались. Временная ветка оставлена для переключения по тикету 14.
- Перед записью в ветке сравнивались только агрегаты и отпечатки всех строк `users`, `habits`, `daily_entries`: они совпали с production (28, 37 и 808 строк). Журнала `schema_migrations` не было в обеих ветках. Повторная сверка 001–004 показала расширение `uuid-ossp`, UUID-ключи `users` и `habits` с `gen_random_uuid()`, ожидаемые `NOT NULL`, `UNIQUE`, внешние ключи с `ON DELETE CASCADE` и все индексы трёх таблиц. У `daily_entries` сохранён `UNIQUE (user_id, date)`, первичный ключ `(user_id, date)`; `id` имеет тип `varchar(255)` без default. Для 005 виден кластер из 266 строк с одинаковым `updated_at` массового преобразования `2026-01-22 01:19:28.309871`; у всех 265 ранних записей с `wakeTime` есть `bedtime` за предыдущий день. Для 006 подтверждены `sleep_data jsonb` с новым default, новые ключи сна во всех 808 записях и отсутствие `napDurationMin`/`durationMin`. Это согласуется с прежней инвентаризацией 001–006; точная история выполнения 005 задним числом не утверждается.
- Из корневого `Dockerfile` собран образ `sadhana-api:rehearsal-776717e`. Команда `node dist/db/migrate.js --baseline-confirmed-001-006` с явным подтверждением на direct endpoint временной ветки завершилась с кодом 0 и сообщением `Recorded confirmed migrations 001–006 without running their SQL`. Журнал содержит только 001–006, `recorded_retrospectively = true`, `applied_at = NULL`; SHA-256 каждой строки совпадает с точными байтами соответствующего неизменённого SQL-файла.
- Два следующих запуска `node dist/db/migrate.js` из того же образа завершились с кодом 0 и сообщением `Migrations are up to date`. Для отрицательной проверки только в контейнер был подмонтирован изменённый локальный файл 001; запуск завершился с кодом 1 и `Migration checksum changed: 001`. Файл в репозитории и журнал не менялись.

SQL 001–006 повторно не исполнялись, персональные строки не выгружались. В production не выполнялись операции записи.
