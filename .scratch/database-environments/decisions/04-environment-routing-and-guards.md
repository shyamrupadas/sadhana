## Question

Как локальный путь web → API → БД выбирает dev-ветку Neon и исключает случайную запись в production при старте, миграции и восстановлении тестовых данных? Определить проверяемый признак целевой базы, согласованность pooled/direct адресов приложения и мигратора, отдельные секреты dev, поведение при недостающей/чужой конфигурации и безопасный способ видеть выбранное окружение без вывода секретов.

Не ограничиваться названием `NODE_ENV` или сменой одного URL: локальный web сейчас использует production API. Решить, какие локальные операции должны отказываться работать при неверной цели, а существующий Railway Pre-Deploy — продолжать выполнять production-миграции. Учитывать, что агенты могут параллельно работать с тестовыми данными, хотя изменения схемы идут по одному.
