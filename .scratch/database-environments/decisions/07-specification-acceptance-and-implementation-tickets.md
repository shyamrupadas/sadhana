## Question

Согласовать с пользователем подготовленную спецификацию, включая границы тестирования, и после её принятия через `to-tickets` опубликовать реализационные задачи с проверенными зависимостями и критериями приёмки.

До живого ответа пользователя спецификация не считается принятой; `Status: ready-for-agent` в ней сам по себе не даёт приёмки. При уточнениях обновить документ, затем получить согласование. Принятие зафиксировать по правилам локального трекера. Не задавать повторно вопросы по уже принятым требованиям. По уточнению пользователя от 2026-10-15, перед проверками и действиями через аккаунт/сервис предлагать выбор: пользователь выполняет шаг сам либо делегирует агенту, включая выяснение доступных агенту фактов.

Разбиение должно охватить защиту окружений, команды и сохранение истории мигратора, совместимые синтетические данные и Git-исходник, восстановление/репетицию, необходимые проверки и состав production-образа, проверку возможностей Neon и первое включение локального пути. Размер задач и зависимости определяются из принятой спецификации, а не заранее выбранной структуры файлов. Фактические ограничения выбранного Neon-пути должны обнаруживаться до создания неподходящих ресурсов; невозможность пути возвращает работу к карте.

Результат — опубликованные реализационные тикеты и валидный граф, не реализация. Выполнение тикетов продолжается отдельными сессиями с `awaiting-human-review` и человеческой приёмкой. Этот билет HITL в части согласования: агент не принимает спецификацию за пользователя.

## Answer

Выполнено 2026-10-15. Пользователь принял спецификацию 2026-10-14, затем согласовал предложенные восемь реализационных тикетов и их зависимости 2026-10-15. Спецификация содержит маркер принятия; разбиение опубликовано через `to-tickets` отдельными файлами в [реализационном трекере перехода](../issues/README.md).

По дополнительному пожеланию пользователь активнее участвует в работе: перед проверкой или действием через аккаунт/сервис, которое он может выполнить сам, агент объясняет цель и ожидаемый результат и предлагает выбор — выполнить самому либо делегировать. Этот шаг ждёт ответа; независимая работа продолжается. Явное делегирование сохраняется на согласованный объём. Правило записано в карте, спецификации и каждом реализационном тикете; прежнее требование не предлагать пользователю выяснение доступных агенту фактов заменено этим осознанным выбором.

До публикации проверены все восемь тикетов, существование и порядок блокировок, совпадение названий, отсутствие повторных/самостоятельных/циклических ссылок. Первые доступные задачи — [«Безопасный локальный путь web → API → dev»](../issues/01-safe-development-routing.md) и [«Проверка SQL в production-образе без фиксированного количества»](../issues/04-production-image-migration-integrity.md). Самая ранняя по порядку — «Безопасный локальный путь web → API → dev».

Подготовка и публикация завершены; реализация не начиналась. Все реализационные тикеты имеют `ready-for-agent`, без маркеров приёмки. БД, env и внешние аккаунты не менялись. Проверки кода не запускались для документационных изменений.
