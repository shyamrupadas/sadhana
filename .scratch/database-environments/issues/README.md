# Реализационные тикеты перехода на dev-БД

Тикеты опубликованы 2026-10-15 по принятой спецификации «Dev-ветка Neon и безопасная проверка миграций» и согласованному пользователем разбиению. Каждый нумерованный файл — отдельная реализационная задача.

Все тикеты имеют статус `ready-for-agent`; начинать можно только задачи с принятыми блокировками. Выполненные задачи переходят в `awaiting-human-review`; только человеческая приёмка разблокирует зависящие задачи.

Пользователь хочет активнее участвовать: перед проверкой или действием через аккаунт/сервис, которое он может выполнить сам, агент объясняет цель/ожидаемый результат и предлагает выбор — выполнить самому либо делегировать агенту. Выбранный шаг ждёт ответа, независимая работа продолжается. Явное делегирование сохраняется на согласованный объём. Правило включено в каждый тикет.

1. [«Безопасный локальный путь web → API → dev»](01-safe-development-routing.md). Без блокирующих задач. Проверяемый запуск приложения, отдельные секреты, отказ при чужой цели и видимая отметка dev.
2. [«Статус и применение миграций с явными PostgreSQL-проверками»](02-migration-commands-and-tests.md). Зависит от «Безопасный локальный путь web → API → dev». Рабочие команды чтения/применения и тестовый прогон существующего мигратора с сохранением истории.
3. [«Первичное заполнение синтетическими профилями»](03-synthetic-development-profiles.md). Зависит от «Статус и применение миграций с явными PostgreSQL-проверками». Три воспроизводимых профиля для обычного входа, ежедневного учёта и длинной истории.
4. [«Проверка SQL в production-образе без фиксированного количества»](04-production-image-migration-integrity.md). Без блокирующих задач. Сверка точного набора и содержимого SQL проверяемой сборки при добавлении следующих миграций.
5. [«Восстановление dev из совместимого Git-исходника»](05-development-reset-from-git.md). Зависит от «Первичное заполнение синтетическими профилями». Полное явное восстановление поддерживаемой схемы и её данных без изменения рабочей копии/index.
6. [«Полная репетиция перехода с проверкой результата»](06-migration-transition-rehearsal.md). Зависит от «Восстановление dev из совместимого Git-исходника». Проверка прежних записей, преобразования и повторного запуска одной командой.
7. [«Создание постоянного dev в Neon и первое заполнение»](07-neon-development-provisioning.md). Зависит от «Полная репетиция перехода с проверкой результата». Проверка аккаунта, создание разрешённой ветки/БД/роли, конфигурация и первоначальное заполнение готовыми командами.
8. [«Включение dev в ежедневную разработку и приёмка перехода»](08-development-cutover-and-verification.md). Зависит от «Создание постоянного dev в Neon и первое заполнение» и «Проверка SQL в production-образе без фиксированного количества». Реальный локальный путь, восстановление/репетиция на Neon и руководство ежедневной работы/выпуска.

Первые доступные задачи — «Безопасный локальный путь web → API → dev» и «Проверка SQL в production-образе без фиксированного количества». Внешние изменения начинаются после готовности команд и проверок. Проверка образа независима от разработки команд; она блокирует только завершение перехода. Остальные зависимости отражают используемые возможности, без повторного перечисления транзитивных блокировок.
