# Реализационные тикеты перехода на dev-БД

Тикеты опубликованы 2026-10-15 по принятой спецификации «Dev-ветка Neon и безопасная проверка миграций» и согласованному пользователем разбиению. Каждый нумерованный файл — отдельная реализационная задача.

Тикет 01 принят 2026-10-15 (`awaiting-human-review`, `Accepted: 2026-10-15`); тикеты 02–04 приняты 2026-10-16 (`awaiting-human-review`, `Accepted: 2026-10-16`), прежняя реализация 05 принята 2026-10-17, затем тикет 05 переоткрыт под согласованное упрощение сброса: обновлённая реализация завершена и имеет статус `awaiting-human-review` без нового `Accepted:`, прежняя приёмка сохранена в Comments. Тикеты 06–08 имеют статус `ready-for-agent`, но ждут повторной приёмки 05 по цепочке зависимостей. Начинать можно только задачи с принятыми блокировками. Выполненные задачи переходят в `awaiting-human-review`; только человеческая приёмка разблокирует зависящие задачи.

Пользователь хочет активнее участвовать: перед проверкой или действием через аккаунт/сервис, которое он может выполнить сам, агент объясняет цель/ожидаемый результат и предлагает выбор — выполнить самому либо делегировать агенту. Выбранный шаг ждёт ответа, независимая работа продолжается. Явное делегирование сохраняется на согласованный объём. Правило включено в каждый тикет. Уточнение от 2026-10-16: Docker и временный PostgreSQL (подготовка, проверки, очистка) полностью делегированы агенту без повторных вопросов; пользователь хочет участвовать в шагах через интерфейс Neon.

1. [«Безопасный локальный путь web → API → dev»](01-safe-development-routing.md). Без блокирующих задач. Проверяемый запуск приложения, отдельные секреты, отказ при чужой цели и видимая отметка dev.
2. [«Статус и применение миграций с явными PostgreSQL-проверками»](02-migration-commands-and-tests.md). Зависит от «Безопасный локальный путь web → API → dev». Рабочие команды чтения/применения и тестовый прогон существующего мигратора с сохранением истории.
3. [«Первичное заполнение синтетическими профилями»](03-synthetic-development-profiles.md). Зависит от «Статус и применение миграций с явными PostgreSQL-проверками». Три воспроизводимых профиля для обычного входа, ежедневного учёта и длинной истории.
4. [«Проверка SQL в production-образе без фиксированного количества»](04-production-image-migration-integrity.md). Без блокирующих задач. Сверка точного набора и содержимого SQL проверяемой сборки при добавлении следующих миграций.
5. [«Восстановление dev из совместимого Git-исходника»](05-development-reset-from-git.md). Зависит от «Первичное заполнение синтетическими профилями». Доработка принятой реализации: транзакционная замена только данных и восстановление исторической `public` внутри той же БД, без служебного подключения/CREATEDB и без изменения рабочей копии/index.
6. [«Полная репетиция перехода с проверкой результата»](06-migration-transition-rehearsal.md). Зависит от «Восстановление dev из совместимого Git-исходника». После повторной приёмки 05: восстановление прежней структуры в той же БД, проверка преобразования записей и повторного запуска одной командой.
7. [«Создание постоянного dev в Neon и первое заполнение»](07-neon-development-provisioning.md). Зависит от «Полная репетиция перехода с проверкой результата». Проверка аккаунта, schema-only ветка с одной рабочей БД, отдельная роль без CREATEDB, права на `public`, конфигурация и первоначальное восстановление/заполнение готовой командой.
8. [«Включение dev в ежедневную разработку и приёмка перехода»](08-development-cutover-and-verification.md). Зависит от «Создание постоянного dev в Neon и первое заполнение» и «Проверка SQL в production-образе без фиксированного количества». Реальный локальный путь, замена данных и восстановление структуры/репетиция на Neon, руководство ежедневной работы/выпуска.

Тикеты 01–04 приняты. Обновлённая задача 05 «Восстановление dev из совместимого Git-исходника» реализована и ожидает повторной человеческой приёмки. Доступных задач сейчас нет: задача 06 заблокирована до повторной приёмки 05. Изменение касается способа сброса и замены данных; история прежней приёмки 05 и исходные зависимости сохранены. Внешние изменения начинаются после готовности команд и проверок. Проверка образа независима от разработки команд; она блокирует только завершение перехода. Остальные зависимости отражают используемые возможности, без повторного перечисления транзитивных блокировок.


Редакция 2026-10-17 отменяет дополнительную dev-БД, обязательные `maintenanceDatabase` и CREATEDB из прежнего плана. Первичное seed (принятый 03) остаётся безопасным заполнением пустых таблиц; новый reseed и восстановление `public` входят в доработку 05. Исторические решения/отчёты отражают прежний контракт; актуальные требования находятся в spec.md и критериях тикетов.
