# 04: Проверка SQL в production-образе без фиксированного количества

**What to build:** Проверка собранного production-образа подтверждает точный набор и содержимое SQL той же сборки. Добавление следующей миграции не требует вручную менять число ожидаемых файлов.

**Blocked by:** None (can start immediately)

**Status:** awaiting-human-review
Accepted: 2026-10-16

- [x] Ожидаемый набор относительных имён и checksum получается из SQL-исходников проверяемой сборки; упакованные файлы сравниваются с этим независимым набором, а не с манифестом, рассчитанным только из содержимого образа.
- [x] Пропущенный, лишний, переименованный или изменённый SQL приводит к отказу проверки. Не остаётся требования «ровно шесть» или другой константы количества.
- [x] Новый корректно добавленный SQL попадает в образ и проходит сверку без изменения ожидаемого числа. Проверка не изменяет реальные исторические SQL и не добавляет тестовую миграцию в выпускаемую цепочку ради демонстрации.
- [x] Сохраняются проверки non-root образа, наличия production-точек запуска/контракта, отсутствия frontend и лишних dev-инструментов, а также проверки старта на Railway PORT. Выпуск не начинает автоматически применять SQL при сборке/старте.
- [x] Подтверждены положительный случай и отказ при отсутствующем/искажённом упакованном SQL. Проверка production-образа выполнена без подключения к Neon; PostgreSQL в обязательный CI не добавляется.

## Проверка и границы

Эта задача не зависит от новых CLI-команд и может выполняться параллельно с защитой окружений. После последующих изменений упаковки итоговая проверка повторяется в приёмке перехода. Внешние настройки Railway и production-БД здесь не меняются.

## Comments

### 2026-10-16 — реализация

- CI перед Docker-сборкой сохраняет относительные имена и SHA-256 исходных SQL; затем тем же скриптом независимо читает SQL из образа и сравнивает полный набор через `diff`. Фиксированное число файлов удалено; пустой набор отклоняется.
- Проверены обычная сборка и отдельная сборка из временного Git-архива с дополнительным SQL: новая сверка успешна, прежнее ограничение количества отклоняет дополнительный файл. Рабочая цепочка SQL не менялась.
- Пропуск, лишний файл, переименование и изменение SQL в одноразовых контейнерах подтверждённо дают отказ (`diff` возвращает `1`).
- Сохранены проверки non-root, production-точек запуска, контракта и отсутствия frontend/dev-инструментов; `migrate.js --help` успешен. Образ с фиктивной тестовой БД ответил `200 {"root":true}` на Railway `PORT=18080`.
- YAML разобран; `git diff --check`, `pnpm typecheck` и `pnpm test` успешны. Workspace-проверки использовали Turbo cache: API 34 успешно, 12 явных DB-сценариев пропущены; contract 10; web 3 и E2E 5.
