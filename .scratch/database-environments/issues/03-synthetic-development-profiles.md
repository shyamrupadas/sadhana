# 03: Первичное заполнение синтетическими профилями

**What to build:** Разработчик одной явной командой получает три тестовых аккаунта с воспроизводимыми привычками и записями дня и входит в них обычной формой. Повторное заполнение не перезаписывает существующую работу.

**Blocked by:** 02 — Статус и применение миграций с явными PostgreSQL-проверками

**Status:** ready-for-agent

- [ ] `pnpm db:dev-seed --date <YYYY-MM-DD>` доступна из корня, имеет справку, требует корректную явную дату и локальный `DEV_FIXTURE_PASSWORD`, использует проверенную dev-цель. Несовместимая схема или существующие прикладные записи вызывают отказ до заполнения.
- [ ] Создаются три аккаунта: пустой без привычек/записей; обычный с привычками и месяцем истории; с привычками и двухлетней историей с пропусками. Email тестовые и устойчивые; конкретный состав набора и способ входа документированы без паролей.
- [ ] Заполненные профили вместе покрывают сон через полночь, неполные ночные времена, дневной сон и его отсутствие, выполненные/невыполненные/отсутствующие отметки и переходы месяцев/лет. Архивирование и новая предметная семантика не добавляются; отдельный 29 февраля не становится обязательным вне целевой миграции.
- [ ] Одинаковые версия генератора и опорная дата воспроизводят одинаковые предметные записи и идентификаторы связей. История заканчивается выбранным московским днём; обычный старт не сдвигает даты и не запускает генератор. Технические времена и солёные хеши не считаются предметной побайтовой воспроизводимостью.
- [ ] Совместимая версия схемы заявлена явно вместе с генератором/набором; первая версия соответствует нынешней цепочке. Заполнение всех исторических схем текущим генератором не обещается. Интерфейс проверки исходного состояния пригоден для последующего восстановления из Git.
- [ ] Заполнение транзакционно: при ошибке нет частичного набора. Пароль всех трёх аккаунтов хешируется обычным способом и не раскрывается; вход использует настоящий API и обычную авторизацию без обхода.
- [ ] API-тесты проверяют известные записи/воспроизводимость и отказ при неподходящей схеме/непустой БД. Явный прогон на разрешённом временном PostgreSQL подтверждает сохранённые записи, транзакционность и обычную авторизацию. Изменения через приложение не перезаписываются новым обычным запуском.

## Проверка и границы

Применять write-tests. Сопоставление известных записей проверяет пользователей, привычки, даты, отметки и сохранённые данные сна, а не только ответы API. Постоянный Neon здесь не создаётся; конкретные примеры будущего преобразования добавляются с самой миграцией.

## Участие пользователя

Когда проверку или действие можно либо поручить агенту, либо выполнить самому через аккаунт/сервис, сначала объяснить цель и ожидаемый результат и предложить пользователю выбор. Этот шаг ждёт ответа; независимая работа может продолжаться. После явного делегирования действовать в согласованном объёме без повторного запроса по тому же шагу. Это предпочтение пользователя от 2026-10-15 действует и для фактов, доступных агенту.
