# 03: Первичное заполнение синтетическими профилями

Архивирование и новая предметная семантика не добавляются; отдельный 29 февраля не становится обязательным вне целевой миграции.
- [x] Одинаковые версия генератора и опорная дата воспроизводят одинаковые предметные записи и идентификаторы связей. История заканчивается выбранным московским днём; обычный старт не сдвигает даты и не запускает генератор. Технические времена и солёные хеши не считаются предметной побайтовой воспроизводимостью.
- [x] Совместимая версия схемы заявлена явно вместе с генератором/набором; первая версия соответствует нынешней цепочке. Заполнение всех исторических схем текущим генератором не обещается. Интерфейс проверки исходного состояния пригоден для последующего восстановления из Git.
- [x] Заполнение транзакционно: при ошибке нет частичного набора. Пароль всех трёх аккаунтов хешируется обычным способом и не раскрывается; вход использует настоящий API и обычную авторизацию без обхода.
- [x] API-тесты проверяют известные записи/воспроизводимость и отказ при неподходящей схеме/непустой БД. Явный прогон на разрешённом временном PostgreSQL подтверждает сохранённые записи, транзакционность и обычную авторизацию. Изменения через приложение не перезаписываются новым обычным запуском.

## Проверка и границы

Применять write-tests. Сопоставление известных записей проверяет пользователей, привычки, даты, отметки и сохранённые данные сна, а не только ответы API. Постоянный Neon здесь не создаётся; конкретные примеры будущего преобразования добавляются с самой миграцией.

Когда проверку или действие можно либо поручить агенту, либо выполнить самому через аккаунт/сервис, сначала объяснить цель и ожидаемый результат и предложить пользователю выбор.
