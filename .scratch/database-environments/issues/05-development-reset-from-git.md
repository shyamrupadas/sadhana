# 05: Восстановление dev из совместимого Git-исходника

**What to build:** Разработчик отдельно обновляет тестовые записи без изменения структуры и восстанавливает поддерживаемую историческую структуру с данными в той же dev-БД. Служебная БД и право CREATEDB для этих команд не нужны; ошибки подготовки сохраняют существующее состояние.

**Blocked by:** 03 — Первичное заполнение синтетическими профилями

**Status:** awaiting-human-review

- [x] `pnpm db:dev-reset --allow-reset --source-ref <git-ref> --to <NNN> --date <YYYY-MM-DD>` доступна из корня со справкой. Все аргументы обязательны; нет скрытых `latest`, текущей даты, произвольной БД/схемы и production-переключателя. Команда восстанавливает `public` внутри той же БД, без `DROP DATABASE`/`CREATE DATABASE`.
- [x] `pnpm db:dev-reseed --allow-reset --date <YYYY-MM-DD>` доступна из корня со справкой. Оба аргумента обязательны. Команда заменяет только прикладные записи набором текущего совместимого генератора, не применяет SQL и не принимает Git-ref, целевую версию или произвольные таблицы. Первичное `db:dev-seed` сохраняет отказ при непустых таблицах.
- [x] Reseed до очистки проверяет независимую dev-цель, применённую совместимую версию и checksum, дату, локальный пароль, готовность набора и известный состав прикладных таблиц/зависимостей. Пользовательские триггеры/правила и неподдерживаемые исполняемые выражения отклоняются до очистки; полный журнал дополнительно сверяется до коммита. Очистка, заполнение и проверка выполняются через одно соединение в одной транзакции с блокировкой записей; заполнение/проверка не открывают новых соединений или собственных транзакций. Ошибка сохраняет прежний набор; структура, расширения, права и полный журнал миграций остаются неизменны.
- [x] Git-ref для reset разрешается в конкретный commit; SQL и совместимый генератор/набор извлекаются во временный каталог без checkout, смены ветки, изменения рабочей копии/index и чтения исторических секретов. Подключение берётся только из текущей проверенной dev-конфигурации; нынешний генератор не подменяет исторический.
- [x] До очистки `public` проверены параметры, SQL/версия, непрерывность/checksum, заявленная совместимость набора и fingerprint проверенного префикса управляемого SQL (`001–006` из `259975c`; иные префиксы требуют явной поддержки), дата, пароль, зависимости и возможность запуска подготовленного кода. Недоступный Git-исходник или неподдерживаемый набор дают отказ без изменений.
- [x] Reset удаляет всю прикладную область `public`, включая экспериментальные таблицы/объекты, `schema_migrations` и объекты `uuid-ossp`, которое заново создаётся SQL `001`. Проверяются фактические объекты/зависимости и права на очистку, создание `public` и поддерживаемые расширения. Неизвестные объекты внутри `public` удаляются. Неподдерживаемые расширения и зависимости между `public` и внешними объектами, включая транзитивные связи в обе стороны, вызывают отказ до очистки; независимые внешние объекты сохраняются. `CASCADE` не изменяет внешние объекты.
- [x] Очистка и создание пустой `public` с правильным владельцем и правами выполняются в одной транзакции; затем общий мигратор применяет исходные SQL до выбранной версии, исторический генератор заполняет таблицы и проверяет исходное состояние. Старый журнал удаляется вместе со структурой, новый создаётся мигратором. Baseline, обратный SQL и выборочное удаление строк журнала не используются; настройки уровня БД не сбрасываются.
- [x] Из общей загрузки dev-конфигурации и примеров удалено обязательное `maintenanceDatabase`; не нужны служебный URL, `resetDatabase` для проверяемой команды и `CREATEDB`/superuser. Имя БД, endpoint, роль и URL сохраняются; проверки независимой цели и фиксированного dev-контекста не ослаблены.
- [x] Пользователь останавливает API и параллельную работу до `--allow-reset`; до очистки проверяется отсутствие посторонних сессий. Команды не завершают чужие соединения/процессы, не выдают advisory lock за блокировку приложения и не обещают предотвратить новое подключение после проверки.
- [x] Ошибка после начала восстановления даёт ненулевой код, безопасно сообщает этап и прочитанное состояние `public`/достигнутую версию либо невозможность чтения. Сохранение самой БД не выдаётся за атомарный возврат прежнего состояния. Повторный явный запуск восстанавливает известный исходник; временные артефакты очищаются при успехе и ошибке.
- [x] API-тесты через fake операции подтверждают отказ до очистки для неверной цели, прав, исходника, неподдерживаемых расширений и внешних зависимостей. Явный PostgreSQL-сценарий на отдельной заранее разрешённой тестовой БД проверяет обе команды под ролью без CREATEDB/superuser: та же БД до/после, восстановленные права/uuid-ossp, удаление экспериментальных объектов, отказ до очистки при внешнем представлении/другой зависимости и неподдерживаемом расширении, ожидаемая версия/данные, повтор после ошибки; для reseed — одно соединение/одна транзакция, неизменность полного журнала/структуры и откат прежних записей при сбое заполнения или проверки. Команда `db:test --target dev` не очищает постоянную `public` или его записи; подготовка/очистка отдельной тестовой БД относятся к тестовому контуру.
- [x] Обновлены API README, CLI-примеры и инструкции DB-проверок: различаются seed/reseed/reset, описаны ограничения управляемой структуры, сохранённые Git-исходники, остановка параллельной работы и поведение после ошибки. Команды БД сами не создают коммиты; перед историческим reset совместимый исходник сохранён обычным Git-процессом.
