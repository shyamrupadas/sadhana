# 05: Восстановление dev из совместимого Git-исходника

**What to build:** Разработчик явно восстанавливает постоянный dev до поддерживаемой версии схемы с совместимыми синтетическими записями. Ошибки подготовки сохраняют текущую БД; извлечение исторического кода не затрагивает рабочую копию и index.

**Blocked by:** 03 — Первичное заполнение синтетическими профилями

**Status:** awaiting-human-review
Accepted: 2026-10-17

- [x] `pnpm db:dev-reset --allow-reset --source-ref <git-ref> --to <NNN> --date <YYYY-MM-DD>` доступна из корня со справкой. Все аргументы обязательны; скрытых `latest`, текущей даты, произвольной целевой БД и production-переключателя нет.
- [x] Git-ref разрешается в конкретный commit; SQL и совместимый генератор/набор извлекаются во временный каталог без checkout, смены ветки, изменения рабочей копии/index и чтения исторических секретов. Подключение берётся только из текущей проверенной dev-конфигурации.
- [x] До удаления БД проверены цель, параметры, доступность SQL/версии, непрерывность/checksum, заявленная совместимость набора, дата, пароль, необходимые зависимости и возможность запуска подготовленного кода. Недоступная Git-версия или неподдерживаемый исходник вызывают отказ без сброса; нынешний генератор не подменяет исторический.
- [x] Служебный канал использует ту же проверенную direct dev-ветку и dev-роль с отдельной заранее разрешённой служебной БД. Проверены необходимые права до разрушительного этапа; прикладной SQL и заполнение там не выполняются. Невозможность выбранного способа требует возвращения к карте, без использования production-роли.
- [x] Пересоздаётся только разрешённая dev-БД; ветка/роль/URL сохраняются. Исходные SQL применяются общим мигратором до выбранной версии, затем выполняются совместимое заполнение и проверка исходного состояния. Baseline, обратный SQL, ручное удаление журнала и Neon reset/restore от production не используются.
- [x] Разрешение сброса явно и не заменяет проверку цели. Пользователь обеспечивает остановку работающих с dev процессов; команда не останавливает чужие агенты/API и не выдаёт advisory lock за общую блокировку приложения.
- [x] Ошибка после начала пересоздания даёт ненулевой код, безопасно сообщает этап и достигнутую версию/отсутствие БД. Атомарный возврат прежнего dev не обещается; повторный запуск восстанавливает известный исходник. Временный код/артефакты очищаются при успехе и ошибке.
- [x] API-тесты через fake операции подтверждают отказ до удаления при ошибках подготовки. Явный PostgreSQL-сценарий с отдельной разрешённой временной БД и служебным каналом подтверждает полное пересоздание, достижение версии/данных и повтор операции после ошибки; постоянный dev при этих тестах не уничтожается.
- [x] Описаны поддерживаемые исходники и необходимость сохранённого в Git генератора. Команда сама не создаёт коммиты. Перед запуском на постоянном dev совместимый исходник должен быть сохранён обычным процессом проекта.

## Проверка и границы

Применять write-tests. Это завершённый сценарий восстановления, а не отдельная горизонтальная задача «Git helper». Он включает проверку, получение кода, служебные операции, миграции и генератор. Производственные секреты и состояние не исследуются и не меняются.

## Участие пользователя

Когда проверку или действие можно либо поручить агенту, либо выполнить самому через аккаунт/сервис, сначала объяснить цель и ожидаемый результат и предложить пользователю выбор. Этот шаг ждёт ответа; независимая работа может продолжаться. После явного делегирования действовать в согласованном объёме без повторного запроса по тому же шагу. Это предпочтение пользователя от 2026-10-15 действует и для фактов, доступных агенту.

Уточнение пользователя от 2026-10-16: все действия с Docker и временным PostgreSQL, включая подготовку, проверки и очистку, делегированы агенту без повторных вопросов. Пользователь хочет участвовать в шагах через интерфейс Neon; для них сохраняется выбор выше.
