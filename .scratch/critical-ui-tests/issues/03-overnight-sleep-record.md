# 03: Сохранение ночного сна

**What to build:** Защитить браузерным UI-тестом второй основной ежедневный путь Sadhana — запись сна. Пользователь вводит вечерний отбой и утренний подъём через полночь и после обновления страницы видит сохранённые данные сна и длительность. Серверные тесты не обнаружат, если интерфейс отправит неверную дату или перестанет показывать сохранённый результат.

**Blocked by:** 01 — Отметка привычки и тестовый контур

## Контекст и границы

- Проверять полный ввод через существующий интерфейс с браузерным тестовым контуром из тикета 01. Точная подмена API хранит запись дня между запросами и обновлением страницы; живой backend и база данных не участвуют.
- Ночной переход через полночь выбран потому, что это типичный и рискованный сценарий для данных сна. Первый набор остаётся малым: один тест защищает ввод и повторное отображение; расчёт на сервере уже покрыт существующими тестами API.
- Полный исходный запрос и общие решения по тестированию находятся в [родительской спецификации](../spec.md). Прочитать её перед реализацией.

## Comments

- Уточнение действующего пользовательского пути: HTTP-контракт считает длительность ночи в записи утреннего дня по отбою предыдущего дня. Поэтому браузерный сценарий вводит отбой `08.10.2026 23:15` в вечерний столбец и подъём `09.10.2026 07:30` в утренний; после обновления показывает сохранённые времена и `8:15` в записи утра. Это конкретизация формулировки «в одну запись дня» без изменения продукта или контракта.
