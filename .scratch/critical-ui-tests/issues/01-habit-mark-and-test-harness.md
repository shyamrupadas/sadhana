# 01: Отметка привычки и тестовый контур

**What to build:** Поднять в Sadhana систему автоматических UI-тестов по референсу ShlokaHub и сразу защитить основной ежедневный путь — отметку привычки. Пользователь должен видеть после обновления страницы каждое сохранённое состояние отметки, а отказ API не должен выглядеть как успешное сохранение. Сейчас тесты API и контракта не проверяют это поведение интерфейса.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Один браузерный сценарий создаёт привычку и проверяет после обновления страницы каждое состояние отметки: «выполнено», «не выполнено», «не отмечена».
- [ ] Один интеграционный UI-тест проверяет, что после отказа API отметка возвращается к прежнему состоянию и пользователь не видит её как сохранённую.
- [ ] Браузерный и интеграционный тесты используют точные подмены API; неожиданный запрос явно диагностируется, реальная база данных не используется.
- [ ] Настроены Vitest/React Testing Library и Playwright Test, отдельные команды для быстрых и браузерных тестов и локальная общая команда, запускающая оба набора, как в ShlokaHub.
- [ ] Правила, руководство и проектный навык описывают уровни тестов, команды, минимально достаточный уровень, запрет дублирования и строгий критерий добавления теста: критичный путь или достоверность данных; при сомнении сценарий согласуется с человеком.
- [ ] Существующая конфигурация Playwright MCP проверена и используется без дублирования; для ручного браузерного прохода применяется `chrome-devtools` MCP, если конкретный навык не требует Playwright.
- [ ] CI сохраняет прежние проверки API, контракта, lint, типов и сборки, запускает быстрый UI-тест и не запускает Playwright.
- [ ] Целевые тесты, `pnpm lint`, `pnpm build` и локальный `pnpm test` проходят; основной путь вручную проверен через `pnpm dev:web`.

## Контекст и границы

- Это первый вертикальный срез всей задачи по UI-тестам: настройка тестового контура, правила его применения и работающие проверки привычки входят в один завершённый результат.
- Цель — малый набор защитных тестов. Уровни тестирования служат для выбора подходящей проверки, а не задают квоты. Тест добавляют, только если поломка перекроет важный пользовательский путь или исказит представление о сохранённых данных; при сомнении о ценности сценария нужно спросить человека.
- Согласованные места проверки: полный путь через браузер для сохранения отметки и страница ежедневных записей с провайдерами и подменённым API для отката после ошибки. Оба теста проверяют разное поведение, без дублирования.
- Использовать устройство инфраструктуры и правила ShlokaHub как референс, адаптируя их к Sadhana. Playwright MCP уже настроен; файловые браузерные тесты требуют отдельного Playwright Test runner. Локальная общая команда включает браузерные тесты, CI — только быстрые UI-тесты вместе с прежними проверками.
- Полный исходный запрос, принятые решения и исключённые сценарии находятся в [родительской спецификации](../spec.md). Прочитать её перед реализацией.
