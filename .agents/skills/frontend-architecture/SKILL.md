# Frontend Architecture

Считай [живые правила архитектуры](../../../docs/architecture/frontend.md) источником истины для размещения модулей и зависимостей. Прочитай [ADR-0001](../../../docs/adr/0001-frontend-layers.md), объясняющий выбор трех слоев, и актуальный spec или ticket, если он есть. Перед структурной правкой сопоставь документы с `eslint.boundaries.js` и текущим кодом.

## Порядок работы

1. Найди затронутые файлы через `rg --files src` и их зависимости узким `rg`-поиском импортов `@/`. Определи ответственность, вызывающий код и текущий публичный интерфейс каждого модуля.
2. Сверь предлагаемую структуру с `docs/architecture/frontend.md` и lint-правилами. Выбери минимальную структуру для реальных ответственностей; детали реализации оставь за небольшим публичным интерфейсом.
3. При архитектурной правке переноси по одной точке разделения модулей. Сохраняй наблюдаемое поведение при структурном переносе, затем обновляй внешние импорты через интерфейс модуля. Запрошенное изменение поведения выполняй отдельно от переноса.
4. Запусти `yarn lint` и `yarn build`; вручную проверь затронутые пользовательские сценарии, если правка может их изменить. Если принято новое архитектурное правило, обнови живой документ и исполняемые lint-правила вместе; при изменении решения пересмотри ADR-0001.

Для запроса только на аудит сообщи выводы без правок файлов.

## Проверка и отчет

Проверь, что у каждого затронутого файла понятная ответственность, зависимости соблюдают три слоя, внешние импорты фич используют публичные входные точки, а интерфейсы модулей остаются небольшими. В отчете укажи измененные ответственности и интерфейсы, выполненные проверки и оставшиеся прямые импорты или временные пути совместимости.
