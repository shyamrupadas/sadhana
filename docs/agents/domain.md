# Domain Docs

Read the root `CONTEXT.md` before work that uses domain terminology, and read relevant decisions in `docs/adr/`. These files are created when terms or decisions are resolved; proceed if they do not exist yet.

## Layout

This is a single-context repo:

- `CONTEXT.md`: canonical domain terms and relationships.
- `docs/adr/`: hard-to-reverse decisions and their reasoning.

Use the glossary's terms in specs, tickets, tests, and code. If a proposed change contradicts an ADR, surface the conflict explicitly.
