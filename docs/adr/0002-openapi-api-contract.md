# Использовать TypeSpec как единый источник HTTP-контракта

Публичные операции Sadhana описаны в `packages/api-contract/main.tsp`. Из TypeSpec генерируются OpenAPI 3.0, типы, именованный `ApiClient` для web и единый `ApiHandlers` для API. Приложения импортируют контракт через публичный вход пакета `@sadhana/api-contract`; собственных редактируемых YAML-схем у них нет.

**Альтернативы и компромисс**

- Отдельные OpenAPI-копии в web и API требуют ручной синхронизации и уже расходились с фактическими маршрутами.
- Ручные типы клиента и обработчиков не гарантируют покрытие всех операций.
- Генерация добавляет шаг сборки и коммитимые производные файлы, зато изменение одной TypeSpec-модели проверяется обоими приложениями.

**Последствия**

При изменении публичного API сначала обновляем `main.tsp`, затем запускаем `pnpm --filter @sadhana/api-contract generate` и включаем изменения в `packages/api-contract/generated/` в тот же diff. CI повторяет генерацию и отклоняет изменённые или новые незакоммиченные артефакты. Generated-файлы не редактируются вручную. Типизация `ApiHandlers` и `ApiClient` дополняет, но не заменяет runtime JSON Schema Fastify и HTTP-тесты поведения, включая ошибки и cookie.
